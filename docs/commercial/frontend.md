# Phase 6: authenticated commercial frontend

## Delivered in this phase
- Supabase browser client using only the public project URL and anon/publishable key.
- Email/password sign-in and sign-up screens.
- First-company onboarding through the existing \`create_company_for_current_user\` RPC.
- Company membership and role loading after authentication.
- Customer/supplier register with company-scoped listing, filters, search and record creation.
- Estimate register and draft creation.
- BOQ section and item entry; quantity × rate line totals are generated by PostgreSQL.
- Estimate submission, approval, rejection and cancellation through the existing permission-controlled RPC.

## Local setup
Copy \`.env.example\` to \`.env.local\` and set:
- \`VITE_SUPABASE_URL\`
- \`VITE_SUPABASE_ANON_KEY\`

Use the public anon/publishable key only. Never put a service-role key in browser environment variables or commit secrets.

## Current limitations
- No test user or company has been provisioned in the development database. Authenticated browser workflows have not yet been exercised end-to-end.
- Party contact-person maintenance, project/contract selectors on estimates, estimate revision cloning, discount/tax editing, BOQ section reassignment/edit/delete, and printable estimate documents are not included yet.
- Estimate tax remains a manual commercial input, not a VAT engine or journal posting.
- The UI relies on database RLS and RPC permissions; it does not replace server-side authorization.
